## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| navegador → PostgREST (`casos`) | El rol de recepción puede insertar/actualizar filas de `casos`; el límite real de qué puede escribir lo pone RLS, no la UI |
| navegador → Storage (`casos-fotos`) | Un archivo subido por el cliente cruza a un bucket privado; el path es el único dato que la política de storage puede validar |
| `estado` como máquina de estados | Un valor de `estado` fuera de los 13 exactos rompe el semáforo del plan 02-04 y cualquier filtro de RLS que compare contra esa lista |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-2-01 | Tampering | columna `estado` de `casos` | mitigate | CHECK constraint con los 13 valores exactos (task 1); `ESTADOS_CASO` en `types.ts` es la única fuente de la lista en TypeScript, evitando que un plan futuro escriba un valor que la base rechazaría en silencio de otra forma |

| T-2-03 | Information Disclosure | bucket `casos-fotos` | mitigate | Bucket privado (`public = false`) + RLS en `storage.objects` parseando `case_id` del path (task 1, punto 6); nunca URL pública, solo `createSignedUrls` con expiración de 1 hora |
