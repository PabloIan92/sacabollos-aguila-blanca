<objective>
Cerrar el alta de usuarios dentro de la app: dueño y recepción crean usuarios con su rol desde una pantalla propia, y la única frontera que decide quién puede otorgar qué es el servidor, no el formulario.

Purpose: es lo que hace autosuficiente al sistema — a partir de acá nadie más necesita entrar al panel de Supabase para dar de alta a una persona (D-01). Y es la primera vez que el proyecto corre código con la clave privilegiada, así que también establece el patrón de "un único lugar server-side, que re-valida todo" que las fases siguientes van a copiar.
Output: Edge Function `invite-user` desplegada, pantalla `/invitar`, y una verificación automatizada de que la escalada de rol se rechaza.
</objective>

## Phase Goal

**As a** dueño (o recepción), **I want to** crear el usuario de una persona nueva del taller desde la propia app, eligiendo su rol, **so that** pueda empezar a trabajar en el sistema sin que yo tenga que entrar a la consola técnica de la base de datos.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| navegador → Edge Function | El cuerpo del pedido es input no confiable y puede armarse sin pasar por el formulario; el JWT prueba identidad, no autorización |
| Edge Function → Admin API de Auth | El único cruce del sistema donde corre código con la clave privilegiada, capaz de crear usuarios y de escribir el rol |
| Edge Function → navegador (respuesta) | La respuesta lleva un secreto de un solo uso: la contraseña temporal |
| runtime de la función → logs | Todo lo que se loguee sobrevive al pedido y puede leerse después |
